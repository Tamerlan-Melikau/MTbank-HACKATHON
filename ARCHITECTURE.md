# Архитектура «Семейного кошелька»

Прототип детско-семейного банкинга в Moby. Статическое SPA (React + TypeScript + Vite), публикуется на GitHub Pages и открывается в браузере любого телефона. Бэкенда нет: банк имитирует `MockBank` прямо в браузере.

Главная идея: **бизнес-правила отделены от интерфейса.** Интерфейс будут переделывать, а возрастные права, лимиты, согласия и авторизацию платежей переписывать не придётся.

## Слои

```
src/
  domain/      Чистые правила и типы. Без React, без хранилища. Покрыт тестами.
  api/         Контракт BankApi + MockBank («сервер в браузере»).
  app/         Связка с React: роутер, хуки данных, сессия, тема, тосты, таблица маршрутов.
  ui/          UI-кит на токенах дизайн-системы. ЗАМЕНЯЕМЫЙ слой.
  features/    Экраны. Собирают данные из app/ и рисуют их компонентами ui/.
```

Зависимости идут только вниз: `features → app, ui → api → domain`. `domain` не импортирует ничего из проекта.

| Слой | Что меняется при редизайне |
|---|---|
| `domain/` | ничего |
| `api/` | ничего |
| `app/` | ничего (кроме `routes.tsx`, если меняется навигация) |
| `ui/` | всё |
| `features/` | разметка экранов; запросы данных и вызовы команд остаются |

## domain/: правила

| Файл | Что в нём |
|---|---|
| `money.ts` | Деньги в копейках (целые числа), формат «1 938,22 BYN», «+» и «−». |
| `age.ts` | Возрастные группы `junior` (7–13) и `teen` (14–17), расчёт по дате рождения. |
| `capabilities.ts` | **Каталог возможностей ребёнка.** Для каждой возможности и группы задан потолок (`ceiling`) и значение по умолчанию. Уровни: `off` < `approval` < `on`. |
| `policy.ts` | **Движок прав.** `capabilityAccess()` возвращает: разрешено / с подтверждением / запрещено (кем: родителем или возрастом; можно ли запросить). |
| `payments.ts` | **Авторизация операции.** `authorizePayment()`: карта → всегда запрещённые категории → канал → категории родителя → баланс → лимиты → подтверждение. Тексты причин для родителя («вы») и ребёнка («ты»). |
| `categories.ts` | Категории покупок. `hardBlocked` (азартные игры, 18+, алкоголь, табак) родитель не может разрешить. |
| `gamification.ts` | Уроки с квизами, уровни, награды (числа — допущения). |
| `products.ts` | Пакет и витрина продуктов (условия — допущения). |
| `requests.ts` | Описание запросов, рекомендованные лимиты по возрасту. |
| `types.ts` | Сущности: семья, участник, настройки ребёнка, согласия, счёт, карта, операция, запрос, задание, баллы, уведомление. |

### Как решается «можно ли»

```
родитель задаёт уровень ─┐
                         ├─► clamp по потолку возраста ─► capabilityAccess() ─► allowed / approval / denied(parent|age)
возрастная группа ───────┘
```

- `denied(parent)` → ребёнок видит замок и кнопку «Запросить у родителя».
- `denied(age)` → «Станет доступно, когда подрастёшь», запросить нельзя.
- Когда ребёнку исполняется 14, группа пересчитывается сама (`syncAgeGroup`), права обрезаются по новому потолку.

### Доступ ребёнка в Moby

Это отдельный жизненный цикл с согласием родителя, а не флаг:

```
none ──(родитель создаёт ребёнка / выдаёт код)──► invited ──(ребёнок ввёл код)──► pending_confirm ──(родитель подтвердил)──► active
active ◄──► suspended (родитель приостановил / вернул)
```

Код одноразовый: после ввода он удаляется. Согласие `child-moby-access` сохраняется в момент подтверждения родителем, а не при вводе кода.

## api/: контракт и «сервер»

- `contract.ts`: интерфейс `BankApi`. Это **единственное**, что видят экраны.
- `mock/server.ts`: `MockBank`, реализация в браузере. Ведёт себя как сервер:
  - проверяет сессию и роль в **каждом** методе (ребёнок не может менять свои права, родитель видит только свою семью);
  - права решает `policy.ts`, платежи `payments.ts`; кнопки в UI только отражают это;
  - команды транзакционны: работа на копии базы, при ошибке ничего не меняется;
  - отдаёт копии данных, держит искусственную задержку 120 мс;
  - «карманные деньги» начисляются по расписанию при обращении (догоняет пропущенные периоды).
- `mock/db.ts`: таблицы. Меняете форму данных — увеличьте `DB_VERSION`, у всех сбросится сид.
- `mock/seed.ts`: демо-семья: родители Анна и Сергей, Миша 10 лет и Катя 15 лет.
- Хранилище: `localStorage` для общей «базы» (все вкладки) и `sessionStorage` для сессии (у каждой вкладки своя). Поэтому **в одной вкладке можно войти родителем, в другой ребёнком**, и изменения видны сразу.

### Подключить настоящий бэкенд

1. Написать `HttpBank implements BankApi` (fetch к REST/GraphQL).
2. В `src/api/index.ts` вернуть его вместо `MockBank`.
3. `subscribe()` реализовать через WebSocket/SSE или опрос.

Экраны менять не нужно.

## app/: связка с React

- `router.tsx`: hash-роутер на 60 строк (`#/child/m_misha`). Hash нужен, потому что GitHub Pages не умеет отдавать `index.html` на глубокие ссылки.
- `routes.tsx`: таблица маршрутов: путь, роли, вкладка. Охрана по ролям здесь для удобства; настоящая проверка прав в API.
- `data.ts`: `useQuery(fn, deps)` загружает данные и перечитывает их при любом изменении в банке; `useAction(fn)` выполняет команду с флагом «выполняется» и тостом ошибки; `useSession()`.
- `theme.ts`: тема system/light/dark через `data-theme` на `<html>`.

## ui/: заменяемый слой

- `theme/tokens.css` **генерируется** из `design-system/project/tokens.json` (`npm run tokens`, запускается автоматически перед `dev` и `build`). Вручную не править.
- `kit.tsx` + `kit.css`: компоненты дизайн-системы (`BalanceHeader`, `QuickActions` (ровно 4), `TabBar` (ровно 4 вкладки), `PromoBanner`) и базовые (`Card`, `Row`, `Button`, `Field`, `Segmented`, `Switch`, `Locked` и др.).
- Компоненты «глупые»: получают готовые строки и колбэки, про API ничего не знают.

## Мобильные устройства

- `viewport-fit=cover` и отступы `env(safe-area-inset-*)`: «чёлка» и home-индикатор iPhone.
- `100dvh`: корректная высота с адресной строкой.
- Поля ввода 16px: иначе iOS увеличивает страницу при фокусе.
- Цели касания не меньше 44×44, отдельные правила для экранов 320–359px.
- PWA-манифест и иконки: «На экран Домой» открывает приложение без интерфейса браузера.
- На десктопе приложение показывается колонкой 480px по центру.
- Сборка под Safari 14+ и Chrome 90+.

## Как добавить функцию

1. **Право?** Добавьте возможность в `domain/capabilities.ts` с потолками для обеих групп и `legalNote`, если нужна юридическая проверка.
2. **Данные?** Расширьте `types.ts` и `db.ts` (`DB_VERSION++`), метод в `BankApi` и `MockBank` с проверкой роли.
3. **Тест** на правило в `domain/*.test.ts` или сценарий в `api/mock/server.test.ts`.
4. **Экран** в `features/<имя>/`, строка в `app/routes.tsx`.
5. Покройте обе роли и состояние «доступ запрещён → запросить у родителя» (`<Locked>`).

## Где нужна юридическая проверка

Помечено в коде полем `legalNote` и комментариями «ТРЕБУЕТ ЮРИДИЧЕСКОЙ ПРОВЕРКИ»:

- дееспособность 6–14 и 14–18 (ГК РБ, ст. 25 и 27; номера и формулировки сверить с актуальной редакцией): `domain/age.ts`;
- перечень всегда запрещённых категорий: `domain/categories.ts`;
- онлайн-покупки для 7–13, вклад с 14 лет, таргетированные предложения детям: `domain/capabilities.ts`;
- схема карты (к счёту родителя или ребёнка): `domain/products.ts`;
- тексты согласий и обработка персональных данных ребёнка: `features/enroll/Enroll.tsx`.

## Допущения

Тарифы, кешбэк 1%, стоимость обслуживания, лимиты по умолчанию, баллы за уроки и цели — допущения прототипа, не данные МТБанка. В интерфейсе они помечены.
